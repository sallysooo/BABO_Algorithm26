- numbers: [a0, a1, a2, ...] 라고 했을 때, 각 숫자마자 선택지는 딱 2개
    - +ai or -ai
    - 즉 매 step마다 2가지 선택지가 있는 이진트리라고 볼 수 있음

- 깊이 0: 아직 아무것도 안 고름 (sum=0)
- 깊이 1: +a0 or -a0
- 깊이 2: 거기서 +a1 or -a1
- ...
- 깊이 n: 모든 숫자에 부호를 붙이고 최종 합이 target인지 확인

- 노드 하나는 2가지 정보로 표현할 수 있음 
-> (i, sum), 즉 (몇 번째 숫자까지 처리했는지 인덱스 i, 누적합 sum)
- 시작 상태는 (0, 0)이고, 그 다음 단계에서는 (i+1, sum + numbers[i]) / (i+1, sum - numbers[i]) 로 확장하면서 트리를 확장해나가면 되겠다!

- 탐색 종료 조건: `i == len(numbers)` 이 되는 시점
    - 이 때 `sum == target` 인 경우: 방법 1개 발견 
    - `sum != target` 인 경우: 버리고 다음 노드
    - 정답의 개수를 세는 문제라서 DFS/BFS가 끝까지 돌면서 leaf node에서 조건을 만족하는 개수만 세면 됨

- DFS를 사용하는 이유?
    - 깊이가 numbers의 길이(n)으로 고정되어 있음
    - 완전 이진 트리 탐색
- dfs(i, sum) 함수 생성 후, 각 i번째 노드에 방문할 때 2개의 재귀호출 수행
    - dfs(i+1, sum+numbers[i])
    - dfs(i+1, sum-numbers[i])
    - 마지막에 i==n이 될 때 sum값과 target 값을 비교하여 cnt++
- 일반적인 그래프 탐색에서는 visited가 필요했지만, 이 문제에서는 같은 (i, sum) 상태가 여러 경로로 도달할 수 있고, 이 문제에서는 "최단 경로"를 구하는게 아니라 경로의 "개수"를 세는 중이라 visited를 사용해서 중복을 제거하게 되면 안되기 때문에 사용하지 않음!
